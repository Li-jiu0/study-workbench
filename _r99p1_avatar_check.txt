================================================================
R99 报告原文「缩小能力不受影响（ZMIN=0.4 实测 ratio 恰 0.4000）」不成立，team-lead 指正正确：

================================================================
二、P1 缺陷与根因
================================================================
`#xtpCropOk` 取样 `sSize = crop / total`，`total = baseScale()*scale`。缩小时 total 变小 → sSize 变大，
但原图尺寸固定。sSize 超过 naturalWidth/Height 后，`ctx.drawImage` 源矩形越界，
浏览器把越界部分当透明 → 叠加白底 fillRect → **产出白边/白角**。缩得越小越严重。

================================================================
三、方案选择：采用【方案 A（夹紧源矩形）】，理由
================================================================
方案 A（本次实施）：`#xtpCropOk` 里把正方形取样框夹进原图边界 ——
  保持 sSize 尽量不变、只平移 sx/sy；仅当原图短边 < sSize 时把 sSize 收到原图短边。
  优点：对所有图片比例鲁棒；不压缩用户可用缩放范围；硬保证无白边。
  取舍：当用户缩到小于裁剪区时，输出图会包含裁剪框以外的像素（构图略变）——可接受，
        因为此时用户本来就是「看整图」，且比产出白边好得多。

方案 B（未采用：动态 ZMIN 下限）：把 scale 下限钉在「图片至少覆盖裁剪区」上，
  即 ZMIN_dynamic = crop / (baseScale()*min(natW,natH))。
  实测否决理由 —— 各比例下该动态下限差异极大且会把小图/横图的可缩范围压到近乎为零：
    竖拍9:16 1000x2000: base=0.37500  ZMIN_dyn = 375/(0.375*1000)=1.0000 → 完全不能缩
    竖拍3:4  1000x1333: base=0.46437  ZMIN_dyn = 375/(0.46437*1000)=0.8076 → 仅能缩到 0.81
    方图     1000x1000: base=0.61900  ZMIN_dyn = 375/(0.619*1000)=0.6059 → 仅能缩到 0.61
    横拍     2000x1000: base=0.61900  ZMIN_dyn = 375/(0.619*1000)=0.6059 → 仅能缩到 0.61
    小图     400x600 :  base=1.03167  ZMIN_dyn = 375/(1.03167*400)=0.9088 → 仅能缩到 0.91
  结论：方案 B 会让「缩小」在多数比例下形同虚设（尤其竖拍 9:16 直接锁死），
        与用户「支持缩放（尤其是缩小）」的诉求冲突。故采用方案 A。

四、改动前后对比（assets/xt-profile.js）
================================================================
位置：`#xtpCropOk` 取样段（现 L2320-2336）
前（L2320-2323）：
  var sx = (((sw - crop) / 2) - STATE.x) / total;
  var sy = (((sh - crop) / 2) - STATE.y) / total;
  var sSize = crop / total;
  var cv = document.createElement('canvas');
后：在 sSize 计算与 canvas 创建之间插入夹紧逻辑：
  var nw = STATE.natW || img.naturalWidth || 0;
  var nh = STATE.natH || img.naturalHeight || 0;
  if (nw > 0 && nh > 0) {
    if (sSize > nw || sSize > nh) { sSize = Math.min(nw, nh); }   // 收到原图短边
    if (sx < 0) { sx = 0; }
    if (sy < 0) { sy = 0; }
    if (sx + sSize > nw) { sx = nw - sSize; }
    if (sy + sSize > nh) { sy = nh - sSize; }
    if (sx < 0) { sx = 0; }   // 二次兜底
    if (sy < 0) { sy = 0; }
  }
（JS 里 Math.min 可用；与 CSS 的 min() 禁令无关。drawImage 一行未动。）
