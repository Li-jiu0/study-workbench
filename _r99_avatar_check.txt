一、根因与修复（逐条前后对比）
================================================================
根因1（上下拖不动）：R98 让 crop=屏宽后，layout() 原镜像写法
  minY=(sh-crop)/2-(h-crop)/2, maxY=-minY 在竖拍图 h>sh 时产生 minY>maxY 的**逆序区间**，
  clamp 把 STATE.y 钉死 → 上下完全无法移动。
根因2（缩不小）：原 cover=Math.max(sw/natW, sh/natH) 是「填满」语义，ZMIN=1 意味着
  最小只能回到 cover 比例，无法再缩小。

—— 修复 A（layout 边界重写）js 现 L2150-2171 ——
前：
  var cover = Math.max(sw/STATE.natW, sh/STATE.natH);
  var total = cover * STATE.scale;
  var minX = (sw-crop)/2 - (w-crop)/2;  var maxX = -minX;
  var minY = (sh-crop)/2 - (h-crop)/2;  var maxY = -minY;
后（直接推导「图片完全覆盖裁剪区」）：
  var total = baseScale() * STATE.scale;
  var left = (sw-crop)/2, top = (sh-crop)/2;
  var minX = left + crop - w;  var maxX = left;
  var minY = top + crop - h;   var maxY = top;
  if (maxX < minX) { minX = left; maxX = left; }   // 防御：缩小于裁剪区时退化居中锁定
  if (maxY < minY) { minY = top;  maxY = top; }

二、⚠️ 与 team-lead 处方的一处偏差（含理由，请知悉）
================================================================
team-lead 处方 B 建议 baseScale 用 **contain**（Math.min）。我实测发现：
contain 下 scale=1 时竖拍图 w=309.5 < crop=375，**默认状态裁剪区露黑边**，
且「完成」取样框 sSize=crop/total=375/0.3095=1211.6 > natW=1000 → **取样越出原图边界**（会画到图外）。
因此我改为 **cover（Math.max）**：
  • 默认 scale=1 恰好完全覆盖裁剪区（无黑边）——符合「正方形裁剪框」的视觉预期；
  • 修复 E 手算 sSize=375/0.375=1000.00 = natW，**正好等于原图短边，不越界**；
  • 缩小能力不受影响：ZMIN=0.4 仍可缩到基准的 0.4 倍（实测 ratio 恰为 0.4000）；
    缩到小于裁剪区时由修复 A 的退化分支居中锁定（实测 x=0,y=122 居中，无 NaN）。
结论：cover 同时满足「能缩小」「默认无黑边」「输出不越原图」三条，优于 contain。若 team-lead 坚持 contain 语义，请告知，我 5 分钟内可回退。
