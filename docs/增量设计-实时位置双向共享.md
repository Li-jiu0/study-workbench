# 增量设计 · 实时位置共享双向化 + 前端修复（2026-XX）

> 范围：只改 `server/routers/liveloc.py` 与 `live-location.html` 两个文件。
> Android 壳（`MainActivity.java` / `LocationShareService.java`）**零改动**；`chat-local.js` 本次**不改**。
> 部署形态：单台服务器，前端 HTML 与后端同仓同机、一次上线即同版本；唯一双版本窗口是 WebView 缓存旧 HTML 的短暂期。

---

## 0. 三个缺陷与对应修法（一句话版）

| 缺陷 | 根因 | 修法 |
|---|---|---|
| 1. 一对好友只有一个共享会话（双向不同屏） | `_LIVE_BY_PEER` 是 `pair→share_id` 一对一映射，start 直接覆盖 | 索引改 `pair→share_id 列表`；`/state` 返回该对/群下**所有** active 会话列表 |
| 2. 前端 `Number(null)=0` → 头像漂到 (0,0) | 会话 active 但 owner 未首报 tick 时 `lat:null`，`Number(null)===0` 通过 isFinite | 显式 `hasFix` 就绪标志 + 前端先判 null/undefined 再 Number |
| 3. 网页端发起共享后无人上报坐标 | tick 仅 owner 可调，owner 只有 APK 原生服务在报 | 页面内 `watchPosition` 兜底 tick（仅在原生通道不可见时启用，协调规则见 §3.4） |

## 1. 服务端设计（liveloc.py）

### 1.1 索引结构：pair→列表（结论：不采用全量遍历）

两种候选：
- **A（采纳）**：`_LIVE_BY_PEER: dict[tuple[int,int], list[str]]`、`_LIVE_BY_GROUP: dict[int, list[str]]`；
- B（弃）：删除二级索引，state 时遍历 `_LIVE` 过滤。

结论：`_LIVE` 单进程量级极小（几十~几百条），遍历在 4s 轮询下也完全扛得住；但改造成本上 A 与 B 几乎相同，A 保持 state 内存命中 O(1)，且 `_drop_indexes` 现有「按 share_id 匹配摘除」语义只需把覆盖改 append/remove，改动面最小。**选 A。**

列表操作约定：
- `_LIVE_BY_PEER[pair]` / `_LIVE_BY_GROUP[gid]` 用 `list`，append 前去重（`if sid not in lst`）；结束/摘除用 `lst.remove(sid)`（try/except 容忍不存在）；列表空则整个键 `pop`，防慢泄漏。

### 1.2 `/api/live/state` 响应契约（新）

```json
{
  "ok": true,
  "active": true,            // 任一会话 active 即 true；全部无 → false
  "count": 2,
  "sessions": [
    {
      "shareId": "a1b2…",    // str，36 内
      "sharerId": 101,       // int，会话发起人（=上报坐标的人）
      "sharerName": "阿星",  // str，User.nickname（批量 db.get(User, id) 一次取齐）
      "lat": 39.9042,        // float | null —— 未首报 tick 时为 null，绝不返回 0
      "lng": 116.4074,       // float | null
      "hasFix": true,        // bool —— lat/lng 均非 null 才 true；前端以此为准
      "updatedAt": 1730000000000,  // epoch 毫秒（_ms(ts)），无 fix 时为 0
      "stale": false         // bool —— 有 fix 但距上次心跳 > 60s（_LIVE_STALE_SEC）
    }
  ],
  // ===== 以下为旧字段兼容层（见 1.3），新前端不读 =====
  "shareId": "…", "sharerId": 0, "lat": null, "lng": null,
  "updatedAt": 0, "stale": true
}
```

- 会话排序：`updatedAt` 降序（最新坐标在前）；同 0 时按内存 dict 稳定序即可，不强求。
- 群聊路径同样返回该群**所有**成员的 active 会话（索引同改 list），群成员身份校验不变。
- 过期仍惰性判定：`_active(it, now)` 为 false 的会话**不进 sessions**，也不主动清理内存（惰性语义保持，量小不构成泄漏；下次 start 对同目标的 `_end_existing` 会兜底清）。
- 日志红线不变：state/tick/start/stop 均不打印 lat/lng。
- **`hasFix` 语义锁定**：`hasFix = (it["lat"] is not None and it["lng"] is not None)`；绝不把 null 转 0、绝不返回 0 坐标。

### 1.3 旧页面兼容层（结论：保留，成本 ~10 行）

评估：前端 HTML 与后端同机部署、一次上线同版本；旧版本只存在于 WebView 磁盘缓存的短暂窗口。旧页面逻辑是 `d.active!==true → 等待`、`Number(d.lat)` 画单 marker——只要顶层字段**仍在且类型不变**，旧页面不会崩，行为退化为「只显示一个 marker」，正是现状，可接受。

决定：**保留顶层旧字段**，取值规则：
- 优先取 **peer 的会话**（`owner == 对方id`，还原旧行为「显示对方的坐标」）；无 peer 会话时取任一会话；一个都没有 → 沿用现有 `active:false` 空响应（第 296-298 行原样保留）。
- 新前端**只读 `sessions[]`**，不读顶层字段；两个消费者互不干扰。

### 1.4 DB 兜底查询改 `.all()`

state 内存未命中（进程重启过）时，私聊/群聊兜底查询从 `.first()` 改 `.all()`，对每行 `_hydrate` 后进 sessions；`_hydrate` 只对 `state=="active"` 的行**写二级索引**（顺带修掉现状「ended 行也会覆盖索引」的隐患，见 §2.4）。

### 1.5 `_end_existing` / `stop` / `tick` 在多会话下的行为

- `_end_existing`（179-193 行）：查询从 `.first()` 改 `.all()`，**把本人（owner==user.id）在同一目标上所有 active 会话全部结束**（不再只结最新一条）。幂等不变：无 active 行直接 return；不落卡片。场景：A 对 B start 两次 → 旧会话被清干净，pair 列表里只剩 A 的新会话 + B 的会话（若有）。
- `start`（129-176 行）：`_LIVE_BY_PEER[_pair(...)] = share_id` 改为 append；其余逻辑（can_message、卡片、expiresAt）不变。start 语义仍是幂等的（先 `end_existing` 自己的旧会话再开新的）。
- `stop`（232-257 行）：**零改动**。它按 shareId 精确停、只停自己的（owner 校验），多会话下天然幂等——A stop 只结束 A 的会话，B 的会话继续。`_drop_indexes` 改为从列表 remove。
- `tick`（196-229 行）：**零改动**。owner 校验 + `_active` 惰性判定与 shareId 一一对应，多会话无歧义。web 兜底 tick 与 APK 原生 tick 打同一 shareId 时服务端是 last-write-wins 覆盖内存坐标，无脏数据、无冲突。
- 60 分钟到期：每会话独立 `exp`，惰性判定逐会话进行，互不影响，零改动。

### 1.6 `_hydrate` 的列表化适配

- `_LIVE_BY_PEER[key] = row.share_id` → append 进列表；`_LIVE_BY_GROUP` 同理。
- **加守护**：仅当回填条目 `not ended`（且未过期）才写二级索引；ended/expired 行只回填 `_LIVE`（供 tick 返回 403「共享已结束」用），绝不进索引。
- `_drop_indexes`：按值 remove（旧代码 `if _LIVE_BY_PEER.get(key)==share_id` 的精确匹配改为 `lst.remove(share_id)` + 空列表 pop 键）。

## 2. 前端设计（live-location.html）

### 2.1 判空修复（修缺陷 2）

新增工具函数（ES2017，var 风格与现页一致）：

```js
function num(v) { return (v === null || v === undefined || v === '') ? NaN : Number(v); }
```

- onState 不再 `Number(d.lat)`：有 `sessions[]` 时逐条 `s.hasFix === true && isFinite(num(s.lat)) && isFinite(num(s.lng))` 才画 marker；`hasFix:false` 的会话**跳过不画**，头像绝不出现在 (0,0)。
- 兼容旧响应（后端未升级或缓存错位时）：`!Array.isArray(d.sessions)` 时回退读顶层 `d.lat/d.lng`（同样过 num() 判空）——保证前端单独热更/回滚都安全。

### 2.2 双（多）marker：按 sharerId 的字典管理

- `var markers = {}`（key = `String(sharerId)`），替换现有单 `marker` 变量。
- 每次收到 sessions：
  1. 对每个 `hasFix:true` 的会话：无 marker → `L.marker(...).addTo(map)` 建；有 → `setLatLng` 更新。
  2. **移除消失者**：上一轮存在、本轮 sessions 中没有（或 hasFix 变 false）的 sharerId → `map.removeLayer(markers[k])` + delete。覆盖「对方停了、我还在」与「我停了、对方还在」两种半结束态。
- 头像/昵称来源三分支：
  - `s.sharerId === myId`（自己）：昵称/头像取**当前登录用户信息**——进页时调一次 `GET /api/auth/me`（Authorization 同 tok()）取 `{id, nickname, avatar}`。**实现前需核对** `server/routers/auth.py` 的 /api/auth/me 返回结构与字段名；localStorage 侧 `study_workbench_uid`（xt-moments.js 在 /api/auth/me 成功后写入）仅作 id 兜底，**不作为昵称/头像来源**（昵称/头像无可靠本地缓存键，以 me 接口为准；me 失败则自己 marker 用首字占位 + 蓝底，与现有 llAvatarIcon 兜底一致）。
  - 对方（私聊）：沿用 URL 参数 `qName/qAvatar`（chat-local.js imLiveViewUrl 附带），逻辑不动。
  - 群聊其他成员：用服务端新增的 `s.sharerName` 首字占位（`llAvatarIcon` 抽成 `llAvatarIcon(name, avatar)` 带参版本）；无 sharerName（旧后端）时占位「星」。
- 底部状态条：任一会话非 stale → 「实时共享中」；全部已 fix 会话均 stale → 「位置已失效」（沿用现有 setBar/stale 样式）。
- 视角（setView）策略：**首次 reveal**（任一 hasFix 出现，false→true）时若有 ≥2 个 marker 用 `map.fitBounds`（maxZoom 16），单个则沿用 `setView([lat,lng])`；此后**不再每次轮询强制居中**（旧代码每 4s setView 一次，双 marker 下会来回跳）。

### 2.3 结束判定

- `d.active !== true`（或 sessions 为空数组）且已 revealed → `showEnded()`（照旧）；
- 只结束一方（session 消失）不算 ended，由 2.2 的移除逻辑处理；全部会话消失才走 ended 层。

### 2.4 网页端 tick 兜底（修缺陷 3，最简版）

触发条件（全部满足才启用）：
1. 本页存在**自己的会话**：sessions 中 `sharerId === myId` 的条目（拿到自己 shareId）；
2. **原生通道不可见**：页面加载即声明 `window.__onLocationUpdate = function(json){ window.__XT_NATIVE_PUSH_AT__ = Date.now(); ... }`（MainActivity.pushLocationUpdate 会向当前 WebView evaluateJavascript 该函数，壳零改动即可作为「原生服务存活心跳」）。**协调规则**：`Date.now() - (__XT_NATIVE_PUSH_AT__||0) > 30000` 才允许 web tick；一旦收到原生推送立刻停掉 watchPosition（原生已接管，APK 内不双跑）。
3. `document.hidden === false`（后台 JS 本就被冻结，显式判断避免语义歧义）。

上报行为（镜像原生节流参数，防刷）：
- `navigator.geolocation.watchPosition`（enableHighAccuracy:true）回调里做节流：**位移 > 30m 或 距上次上报 ≥ 15s** 才 `POST /api/live/tick {shareId, lat, lng}`（首次 fix 立即上报一次）；
- tick 返回 403（会话已结束/过期）→ `clearWatch` 停兜底；网络失败静默（下次节流窗口自然重试），不 toast 刷屏；
- 自己的会话从 sessions 消失（已 stop）→ 停兜底。

权限被拒：
- `watchPosition` 的 error 回调 `PERMISSION_DENIED` → `toast('未授权定位，网页端无法上报你的位置')` + 底部条追加提示（例如文案「对方看不到你的位置」），**不影响继续轮询观看对方坐标**。

不启用兜底的情形：查看别人共享（无自己会话）、群聊未发起者、原生壳内（规则 2 拦截）。纯浏览器私聊发起者 → 兜底生效，缺陷 3 关闭。

## 3. 并发 / 边界矩阵

| 场景 | 行为 |
|---|---|
| A、B 各自 start 同一对 | pair 列表两条会话；双方 `/state` 各见 2 条（自己 + 对方），各自画双 marker |
| 已有会话再 start（同目标） | `_end_existing` 清光自己旧会话（全部，不只最新）→ 只剩自己的新会话 + 对方的（若有）；幂等不报错 |
| A stop 自己 shareId | 只摘 A 的：内存 remove + DB 置 ended + 落「已结束」卡片（was_active 判定不变）；B 的会话继续，B 端 A 的 marker 在下次轮询被移除 |
| 60 分钟到期 | 逐会话惰性过期，不进 sessions；不落卡片（现状不变）；A 再 start 时 `_end_existing` 兜底清 DB |
| 进程重启 | 内存清零 → state 走 DB `.all()` 兜底，active 行回填 `_LIVE` + 列表索引（ended 行不进索引）；`last_db_hb` 重置 → 下次 tick 立即落一次 DB 心跳，无害 |
| 双通道 tick 并发（原生 + web 过渡期） | 同一 shareId 服务端 last-write-wins，坐标均为 owner 本人真实位置，无脏数据；web 侧 30s 心跳规则让过渡窗口 ≤30s |
| 旧缓存页面 + 新后端 | 顶层兼容字段保活，旧页面单 marker 照旧，不崩 |
| 新页面 + 旧后端（回滚） | sessions 非数组 → 回退顶层单会话渲染，不崩 |

## 5. QA 验证要点

- [ ] **(0,0) 红线**：A start 后不 tick，B 打开页面 → A 的会话 `hasFix:false`，B 地图上**无 A marker**、保持「正在获取位置…」占位；绝不能出现几内亚湾 (0,0)。
- [ ] **双方互见**：A、B 各自 start → 双方页面同时看到两个头像（自己 + 对方），坐标各自独立移动；A stop → B 端 A 的 marker 消失但 B 自己的会话与 marker 不受影响。
- [ ] **web 兜底 tick**：浏览器（无壳）A start → A 页面在未授权前/授权后行为正确；授权后 B 端 4s 内看到 A 坐标出现（首报立即上报）。
- [ ] **双通道不冲突**：APK 内 A start（原生服务在报）→ 打开 live-location.html → 日志/网络面板确认 30s 内 web 侧**未发** tick（原生心跳拦截生效）；原生服务杀掉 30s 后 web 兜底接管。
- [ ] **重复 start 幂等**：同一人连点 start → pair 下自己的旧会话被清，DB 无 active 残留、无重复卡片刷屏。
- [ ] **旧兼容**：清缓存前打开过的旧页面（或 curl 断言）→ 新后端响应含顶层 lat/lng/shareId 且类型不变，旧页面不白屏不崩。
- [ ] **到期**：会话过 60 分钟（可临时调短 `_LIVE_SHARE_MAX_SEC` 验证）→ 不进 sessions、B 端正确走 ended 层或仅剩对方会话。
- [ ] **重启兜底**：重启 uvicorn 后 state 仍能从 DB 回填双方会话；ended 行不进索引（tick 该 shareId 返回 403）。
- [ ] **隐私回归**：state 响应无轨迹字段；服务端日志无 lat/lng 明文；geocoder 出网为 0。
