# 星途平台・全模块优化升级版指令手册

在原《名不副实模块改造指令手册》基础上，补充产品体验、视觉、交互、状态、数据与验收要求

> 本版在原手册基础上，保留原有硬性要求，并补充产品体验、视觉、交互、状态、数据和验收标准。

## 一、总纲：本次升级的核心目标

- 目标不是简单把弹窗改成网页，而是把每个“名不副实”的入口真正做成与名称匹配、可长期使用的学习产品。
- 全站统一原则：学习功能使用独立 HTML 页面；主要功能禁止弹窗/模态框；页面之间使用 location.href 跳转；题库、案例、企业资料、话术等数据独立 JSON；页面复用现有 CSS；localStorage key 必须带当前用户名。
- 所有模考/练习页面必须支持多题型混合渲染。统一使用 renderQuestion(question) 根据 type 分发组件，不得只实现 single_choice。
- 视觉目标：减少 Emoji，统一线性 SVG 图标、圆角、间距、字体层级、按钮规范、状态色和反馈动画；不为了“高级”堆装饰，优先保证信息层级和可操作性。
- 所有页面都必须考虑四种状态：正常、加载、空数据、错误。涉及保存/提交的页面还必须提供“已保存/提交成功/恢复进度”等反馈。

## 二、模块1：四级模拟模考

- 现有问题：真题模考被做成弹窗或选择题小测，与“完整四级模拟考试”定位不符。
- 页面结构必须为：mock_exam.html（选卷）→ mock_exam_run.html（全屏考试）→ mock_exam_result.html（成绩）+ mock_exam_papers.json。禁止把三者塞进弹窗。
- 选卷页优化：顶部显示“模拟模考”和“按真实考试时间计时，自动判分”；每套卷使用大卡片，显示卷名、写作/听力/阅读/翻译题型分布、总题数、125分钟、难度、历史最高分和当前状态。
- 增加考试状态：未开始、进行中、已完成。进行中显示已答 X/Y、剩余时间和“继续考试”；已完成显示成绩、正确率和“查看成绩/再次挑战”。
- 考试页优化：固定顶部栏显示卷名、当前题/总题、倒计时、交卷；主体 70% 题目区 + 30% 固定答题卡；增加“写作→听力→阅读→翻译”的阶段进度。
- 答题卡按题型分组，未答灰色、已答绿色、当前题蓝色边框；显示已答 X/Y；点击题号直接跳转。
- 题型必须支持 9 种：single_choice、multiple_choice、true_false、reading、cloze、essay、translation、listening、fill_blank。客观题自动判分，主观题不自动评分而展示参考范文/译文。
- 写作必须有大 textarea、字数统计、自动保存；翻译必须有中文原文、英文输入、字数统计；听力必须有播放/暂停、进度条和时间显示；阅读必须文章与小题同时可见；完形填空必须是文章+编号空+下拉选项。
- 计时器用 setInterval；刷新不丢失；时间到自动交卷；交卷前确认未答题数量；所有答题进度和剩余时间写入当前用户前缀的 localStorage。
- 成绩页优化：总分视觉中心、各部分表现、正确率、题目回顾、客观题解析、主观题参考答案、再次考试和返回选卷。可增加薄弱项提示，但不得伪造主观题自动评分。
- 绝对禁止：5题/15分钟冒充完整模考；只有 A/B/C/D；没有计时器；没有答题卡；没有独立成绩页。

## 三、模块2：四级阅读理解

- 现有问题：弹窗里只有“技巧题”，没有文章，导致“阅读理解”名不副实。
- 页面结构：reading_list.html（文章列表）→ reading_practice.html（阅读练习）+ reading_articles.json。
- 列表页优化：标题、难度筛选（全部/简单/中等/困难）、主题筛选可选；卡片显示标题、主题、词数、难度、5题、开始阅读；支持分页或加载更多。
- 练习页采用上下双区：上半部分文章独立滚动，下半部分一次显示一道题。顶部固定显示标题、第 X/5 题、返回列表。
- 文章视觉：最大宽度适中、行高约1.6、段落间距明显、英文阅读区域不要过度压缩；移动端允许文章区自然滚动。
- 题型建议覆盖细节、主旨、推断、词义四类，数量保持 2/1/1/1。每题答完后进入下一题，全部完成后查看结果。
- 结果区显示  X/5、每题你的答案、正确答案、两句话解析；增加错题定位到文章段落的能力（如果数据有段落标识）。
- 技术要求：至少10篇文章，每篇5题；文章正文与题目必须来自 JSON；进度保存到 localStorage。
- 绝对禁止：没有文章只有题；把技巧题冒充阅读；弹窗答题。

## 四、模块3：四级翻译

- 现有问题：弹窗里用选择题代替翻译，用户无法真正输入翻译。
- 页面结构：translation_list.html → translation_practice.html + translation_passages.json。
- 列表页：主题筛选（中国文化/历史/经济/社会/科技）；卡片显示主题、中文前30字预览、字数、开始翻译。
- 练习页：顶部标题和返回；中文原文使用清晰的大字号；中间大 textarea；底部提交翻译。
- 提交后展开结果，不跳失用户答案：你的翻译、参考译文、逐句中英对照、高频表达5条、下一篇。
- 增加“草稿已保存”状态；再次进入同一题时恢复上次未提交内容。已提交内容允许回看。
- 不要用假 AI 评分。当前版本只做参考译文和表达对比；如果未来增加评分，应作为独立功能。
- 至少15篇，每篇150–200字；必须有 sentences 数组支持逐句对比。
- 绝对禁止：选择题冒充翻译；没有输入框；只有一整篇参考译文；弹窗。

## 五、模块4：情景式口语

- 现有问题：只是听力/跟读标签，没有真正的多轮对话。
- 页面结构：speaking_scenarios.html → speaking_dialog.html + speaking_scenarios.json，必须独立于听力训练。
- 场景列表采用2列卡片网格；每张显示场景名称、统一 SVG 图标、难度、轮数、开始对话。
- 对话页做成完整聊天界面：AI 左侧气泡带头像，用户右侧气泡；顶部显示场景、第 X/总轮数和返回场景。
- AI 发言自动 speechSynthesis；用户输入文字后发送；关键词匹配成功进入下一轮，失败提示建议包含哪些关键词并允许重答。
- 增加对话状态：等待 AI、等待用户、匹配成功、重试、完成；避免用户连续点击造成重复消息。
- 每轮提供“播放发音”和“查看参考答案”；完成后显示轮数、关键词匹配率和学习建议。
- 至少6个场景，每个5–8轮；语音输入明确标注“语音输入开发中，目前支持文字输入”。
- 绝对禁止：单句跟读冒充对话；与听力共用页面；弹窗。

## 六、模块5：央国企综合知识

- 现有问题：名称是“高频考点卡片”，实际却是选择题弹窗。
- 页面结构：knowledge_cards.html（卡片学习）→ knowledge_quiz.html（练习）+ knowledge_cards.json。
- 卡片页中心使用约600×400大卡片，正面显示考点标题、科目标签、学习提示；点击后 CSS 3D rotateY 翻转到背面。
- 背面至少包含3–5条核心要点、1道例题、答案和简析；不能只写一句话。
- 底部提供上一张、下一张、标记已掌握、进度和开始练习。已掌握后变绿色并支持下次跳过。
- 增加“未掌握/已掌握/全部”筛选，方便复习闭环；掌握状态按当前用户写入 localStorage。
- 练习页从卡片例题扩展为10道选择题，答完显示正确率和解析；练习结果可记录。
- 至少80张卡片：经济20、管理20、法律20、计算机20。
- 绝对禁止：只有选择题没有卡片；卡片只有一句话；弹窗。

## 七、模块6：央国企企业定向库

- 现有问题：企业弹窗只有企业名称或1–2句概括，没有形成真正的企业备考资料库。
- 页面结构：company_list.html → company_detail.html + companies.json。
- 列表页采用2/3列企业卡片；显示首字母 Logo 占位、企业名称、行业标签、查看详情；提供行业筛选：能源/建筑/通信/金融/其他。
- 详情页至少五个区块：企业文化、笔试形式、笔试经验、备考建议、相关新闻。
- 企业文化：使命、愿景、核心价值观；笔试形式：题型、题量、时长、难度、是否考英语，用表格呈现。
- 笔试经验必须是带日期和来源标注的真实经验数据；每家至少3条，每条不少于50字。若暂无资料，必须明确标注“待更新”，不得伪造来源。
- 备考建议采用阶段化时间线或步骤卡，而不是一整段文字。
- 相关新闻可留空并标记待更新，避免页面出现空白断层。
- 至少10家企业；详情页内容必须充实。
- 绝对禁止：只放企业名称；每家一句话；没有笔试形式和经验；编造所谓真实来源。

## 八、模块7：高情商案例拆解库

- 现有问题：8道选择题被称为“案例拆解”，实际上没有逐句拆解。
- 页面结构：eq_cases_list.html → eq_case_detail.html + eq_cases.json。
- 列表页按向上沟通/同事协作/拒绝/道歉/赞美/客户沟通筛选；卡片显示标题、1句简介、对话轮数、查看拆解。
- 详情页顶部显示标题、场景标签、返回；先给场景背景，再进入聊天式逐句分析。
- 每句话必须独立成气泡，标注说话人 A/B；每句话下面有“分析”，展开后显示“好在哪/问题在哪”和1–2个更好的说法。
- 分析默认折叠，避免页面过长；点击后平滑展开。用户回复区提供“如果是你，你会怎么说？”输入框，并在本地记录，不做 AI 评判。
- 底部案例总结至少3条核心沟通原则，可增加“我学到了”勾选状态。
- 至少10个案例，每个5–8句；每句话必须有 analysis 和 better 数据。
- 对话气泡复用私聊页面视觉规范，确保全站一致。
- 绝对禁止：选择题冒充拆解；只有对话没有分析；弹窗。

## 九、模块8：i 人沟通专区

- 现有问题：只有5条泛泛建议，没有“提前准备”和“文字辅助”工具。
- 页面结构：iren_scenarios.html → iren_scenario_detail.html、prep_checklist.html、reply_helper.html + iren_data.json。
- 首页顶部标题“i 人沟通专区”，副标题强调“不用变 e 人，用 i 人的方式沟通”。
- 场景区至少15个场景网格；工具区固定提供“社交前准备清单”和“文字回复助手”。
- 场景详情：场景描述、i 人典型心理、保守/适中/直接三套话术、每套话术的具体文本+技巧+适用时机、3条注意事项。
- 准备清单工具：输入场合+选择团建/会议/聚会/面试/相亲/其他；生成3个可聊话题、3个可问问题、2个退出借口、社交能量管理提醒。使用预设模板，不需要 AI。
- 回复助手：输入对方说的话；关键词匹配预设库，生成温和/中立/直接三种回复；每条提供复制按钮；找不到关键词时显示通用回复而不是空白。
- 记录用户最近使用场景/回复到 localStorage 时必须使用用户名作为前缀。
- 绝对禁止：只有5条建议；没有工具页；把工具做成知识卡片；弹窗。

## 十、模块9：商务礼仪 SVG 插画

- 现有问题：页面写“SVG插画”，实际使用 Emoji。
- 不改变原页面结构，只替换视觉资源。生成8个独立 SVG：男士商务着装、女士商务着装、握手礼仪、名片交换、会议礼仪、餐桌礼仪、电话礼仪、办公礼仪。
- 风格必须统一：扁平风、线条简洁、平台主色调蓝色系+橙色点缀、400×300px。
- 文件名固定为 etiquette_1.svg 至 etiquette_8.svg；页面中使用 img 或内联方式引用统一资源。
- 插画需要在桌面和移动端保持清晰，不使用低分辨率位图替代。
- 不要每个页面临时画一套风格不同的插画。

## 十一、模块10：全局图标系统

- 现有问题：Emoji、文字、图片图标混用，尺寸和风格不一致。
- 建立公共 js/icons.js，统一使用 Lucide/Remix 等同一套线性 SVG 图标；颜色统一使用 currentColor。
- 导航图标：home、study/book-open、message、profile/user；学习模块：cet4/graduation-cap、exam/file-text、eq/heart、interview/briefcase、ppt/presentation。
- 操作图标：play、pause、check、close、arrow-left、arrow-right、clock、edit、delete、search、plus、star、fire、trophy、headphones、pen、book-open、mic、languages、chart、settings、logout；状态图标：locked、done、in-progress。
- 统一 getIcon(name,size) API；页面使用 <span class="icon" data-icon="..." data-size="..."></span>，由公共 JS 渲染。
- CSS统一：icon inline-flex；svg 统一 viewBox 24×24、fill none、stroke currentColor、stroke-width 2、圆角线帽和连接；导航约22–24px，模块约32px，按钮约18px。
- 所有页面统一替换 Emoji，不允许单独页面手写另一套 SVG。
- 验收：全站无功能 Emoji；选中/hover颜色正确；不同尺寸清晰；icons.js 可正常运行；所有图标来自明确的开源/免费来源。

## 十二、全站视觉与交互统一升级

- 建立设计令牌：主色、背景色、文字主色/次色、边框色、成功/警告/错误色、圆角、阴影、间距、字体层级，统一写入公共 CSS 变量。
- 按钮分为主按钮、次按钮、文字按钮、危险按钮；同一语义在全站必须长得一样。
- 卡片统一圆角和内边距；重要信息优先级高于装饰；不要所有卡片都使用相同的强阴影。
- 统一页面顶部结构：标题、说明、返回/筛选/操作；不要每个页面自行发明不同头部。
- 所有交互提供 hover、active、focus、disabled 状态；键盘操作和移动端触控区域不得过小。
- 所有列表页支持空状态；数据加载显示轻量 skeleton 或加载提示；JSON 加载失败显示明确错误与重试。
- 所有保存动作给出轻量状态反馈，如“已保存”；禁止使用大弹窗阻断学习流程。
- 页面跳转统一 location.href + query 参数；禁止依赖隐式弹窗导航。
- 移动端优先检查：横向溢出、固定头部遮挡、textarea高度、答题卡宽度、按钮触控面积、字体过小等问题。
- 动画克制：卡片翻转、页面展开、按钮反馈可有 150–300ms 过渡；禁止大量炫技动画影响学习。

## 十三、数据与本地存储统一规范

- 所有题库、文章、翻译、口语、知识卡片、企业、案例、i人话术都使用独立 JSON，通过 fetch 加载，HTML 不写死大批数据。
- JSON 数据必须结构稳定、id 唯一、字段命名统一；缺失数据时页面不能直接崩溃。
- localStorage key 格式统一为 <用户名>_<功能名>_<标识>；禁止使用没有用户名的全局 key。
- 涉及进度的数据必须可恢复；用户刷新、返回再进入时尽量恢复学习状态。
- 不要在 localStorage 保存不必要的敏感信息；只保存完成学习流程所需的数据。

## 十四、最终验收清单（给开发 AI 的强制检查）

- 1. 全站学习功能是否仍存在主要弹窗？有则删除并改独立页面。
- 2. 每个模块是否真的与名称匹配？阅读必须有文章，翻译必须能输入，案例必须逐句分析，口语必须多轮对话，知识必须有卡片，企业必须有详情。
- 3. 模考/练习是否支持9种题型？是否存在统一 renderQuestion(question)？
- 4. 所有数据是否从 JSON fetch 加载？是否还有大量题目写死在 HTML？
- 5. localStorage key 是否带当前用户名？
- 6. 是否有加载、空数据、错误、已保存、已完成等状态？
- 7. 是否支持刷新恢复进度？
- 8. 页面是否能从列表页进入详情/练习页，再回到列表？
- 9. 是否存在移动端横向滚动、按钮过小、固定栏遮挡、文字溢出？
- 10. 是否仍有 Emoji 功能图标？如果有，统一替换为 icons.js。
- 11. 是否把主观题错误地做成自动评分？如果有，改为参考答案展示。
- 12. 是否存在假数据冒充真实来源？企业经验等内容必须有来源字段；没有可靠来源就标注待更新。
- 13. 所有页面是否输出完整可运行文件，而不是代码片段。
- 14. 每个模块完成后先测试，再进入下一个模块；不要一次性重构全部模块导致难以排错。

## 十五、推荐实施顺序

- 第一阶段：先做全局 icons.js + 公共 CSS 规范，避免后面每个页面继续产生 Emoji 和样式分叉。
- 第二阶段：重做四级模拟模考，因为它的页面、题型、计时、答题卡和成绩系统最复杂，可以验证整个学习引擎。
- 第三阶段：阅读理解、翻译，这两个模块可以复用模考中的题型和结果组件。
- 第四阶段：情景式口语、高情商案例拆解、i 人沟通，这三个模块可以复用聊天气泡和本地记录能力。
- 第五阶段：综合知识、企业定向库，重点完善数据质量和详情内容。
- 第六阶段：商务礼仪 SVG 与全站最终视觉验收。
- 每阶段都必须进行“功能验收 + 数据验收 + UI验收 + 移动端验收”，通过后再进入下一阶段。

## 十六、最终产品定位

- 星途不是把若干选择题拼在一起的学习网页，而应形成“入口 → 内容 → 实际练习 → 反馈 → 记录 → 再学习”的闭环。
- 四级模考强调真实考试；阅读强调真实文章；翻译强调真实输出；口语强调真实对话；综合知识强调知识卡片；企业库强调定向备考；高情商和 i人模块强调可直接使用的话术与分析；商务礼仪强调视觉理解。
- 所有优化都以“名副其实、真正可用、长期可扩展、视觉统一”为判断标准，而不是单纯增加按钮或动画。
