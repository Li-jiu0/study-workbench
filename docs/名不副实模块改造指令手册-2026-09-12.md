# 星途平台・名不副实模块改造指令手册

> 用途：直接复制每个模块的指令发给 AI，让 AI 按页面结构级要求改造，杜绝弹窗。
> 生成时间：2026-09-12
> 原则：所有学习功能必须是独立 HTML 页面，绝对禁止弹窗。



***

## 通用前置指令（每次发模块指令前先发这个）



```
【全局规则，所有模块都必须遵守】

1\\\\. 绝对禁止使用弹窗/模态框/overlay/dialog做主要功能页面。

\\\&#x20;  所有学习功能必须是独立的HTML页面，用 location.href 跳转。

2\\\\. 每个功能至少包含：列表页（选内容）+ 详情/练习页（实际操作）。

3\\\\. 所有题库/案例/话术数据存成独立的JSON文件，页面用fetch加载，

\\\&#x20;  不要把题目写死在HTML里。

4\\\\. 页面样式复用现有项目的CSS类，保持视觉统一。

5\\\\. 所有localStorage的key必须带当前用户名前缀，格式：<用户名>\\\\\\\_<功能名>\\\\\\\_<标识>。

6\\\\. 输出完整的可运行文件，不要只给代码片段。

7\\\\. 如果我没说"可以用弹窗"，就一律用独立页面。

8\\\\. 【多题型支持·最重要】所有模考/练习页面必须支持多种题型混合渲染，

\&#x20;  禁止只做选择题。根据JSON里每道题的type字段，用不同的渲染组件：

\&#x20;  \\- single\\\_choice：单选题（4选项，选一个即选中）

\&#x20;  \\- multiple\\\_choice：多选题（4选项，可勾选多个，有"提交答案"按钮）

\&#x20;  \\- true\\\_false：判断题（对/错两个大按钮）

\&#x20;  \\- reading：阅读理解（上方文章独立滚动区+下方题目，题目内嵌单选/多选）

\&#x20;  \\- cloze：完形填空（一篇文章带多个编号空，每个空4选项下拉）

\&#x20;  \\- essay：写作题（题目要求+大文本textarea，高度≥200px）

\&#x20;  \\- translation：翻译题（中文原文显示+英文输入textarea）

\&#x20;  \\- listening：听力题（音频播放按钮+进度条+题目+选项）

\&#x20;  \\- fill\\\_blank：填空题（题干带\\\_\\\_\\\_横线+输入框）

\&#x20;  每种题型判分方式不同：客观题自动判分，主观题显示参考答案不自动评分。

\&#x20;  答题页必须写一个统一的 renderQuestion(question) 函数，

\&#x20;  根据 type 字段 switch 到不同组件，禁止写死只渲染单选题。
```

## 模块 1：四级模拟模考（原 "真题模考"）

**现状问题**：只是一个弹窗，里面 5 条考试攻略折叠面板，没有真题、没有计时、没有答题。

**改造要求**：做 3 个独立 HTML 页面 + 1 个 JSON 数据文件。

### 页面 1：mock\_exam.html（选卷页）

页面布局：



* 顶部：页面标题 "模拟模考" + 副标题 "按真实考试时间计时，自动判分"

* 主体：卷子列表，每套卷子是一个大卡片（宽度占满内容区，高度约 120px）

  每张卡片包含：


  * 卷子名称（如 "四级模拟卷 A"）

  * 题型分布（写作 1 题 + 听力 25 题 + 阅读 30 题 + 翻译 1 题）

  * 总题数、总时长（125 分钟）、难度标签

  * 右侧 "开始考试" 按钮

* 底部："考试指南" 链接（原来的攻略内容移到这里，单独一个小页面 exam\_guide.html）

### 页面 2：mock\_exam\_run.html（答题页，全屏）

顶部固定栏（position:fixed，不随滚动消失）：



* 左侧：卷子名称 + "第 X 题 / 共 Y 题"

* 中间：倒计时，格式 00:00:00，红色字体，时间到自动交卷

* 右侧："交卷" 按钮（点击弹确认框，确认后跳转成绩页）

主体左右分栏：



* 左侧 70%（当前题目区）：


  * 顶部显示当前题型标签（如 "写作"/"听力・短篇新闻"/"阅读・仔细阅读"/"翻译"）

  * 【重点】题目区必须根据题型 type 动态渲染，禁止只做选择题。

    每种题型的渲染规范如下：

    **① 单选题（single\_choice）**

    **② 多选题（multiple\_choice）**

    **③ 判断题（true\_false）**

    **④ 阅读理解题（reading）**

    **⑤ 完形填空（cloze）**

    **⑥ 写作题（essay）**

    **⑦ 翻译题（translation）**

    **⑧ 听力题（listening）**

    **⑨ 填空题（fill\_blank）**


    * 题干文字

    * 4 个选项 A/B/C/D，垂直排列，每个选项是一个可点击的卡片

    * 点击选项即选中，选中后选项边框变蓝、背景浅蓝

    * 不需要 "提交" 按钮，选中即保存答案

    * 题干文字 + 提示 "（多选）"

    * 4 个选项，每个选项前有复选框☐，可勾选多个

    * 底部有 "提交答案" 按钮，点击后才判分

    * 提交后显示对错，正确选项绿色，错误选择红色

    * 题干文字

    * 两个大按钮并排："✓ 正确" / "✗ 错误"

    * 点击即选中，选中高亮

    * 上半部分：阅读文章区（独立滚动，最大高度 300px，有边框）

    * 下半部分：题目区，一篇文章对应 3-5 道小题

    * 小题可以是单选或多选，按上面的规则渲染

    * 文章和题目同时可见，不需要切换

    * 一篇完整文章，文中有编号空格（如 ⑴ ⑵ ⑶）

    * 每个空格下方或右侧有 4 个选项下拉菜单

    * 用户逐个选择，选完一个自动跳到下一个

    * 题目要求（含字数要求、写作要点）

    * 大文本输入框 textarea，高度≥250px

    * 底部实时字数统计："已输入 XX 字"

    * 不自动判分，成绩页显示参考范文

    * 上半部分：中文原文（大字体，灰色背景框）

    * 下半部分：英文输入 textarea，高度≥200px

    * 底部字数统计

    * 不自动判分，成绩页显示参考译文

    * 顶部：音频播放器（播放 / 暂停按钮 + 进度条 + 时间显示）

    * 音频下方：题目 + 选项（单选或多选）

    * 听力材料可以是一题一段音频，也可以是一段音频配多题

    * 音频 URL 在 JSON 里给，暂时可以用占位文本 "音频待添加"

    * 题干中带\_\_\_横线

    * 横线位置是输入框，用户输入答案

    * 提交后比对答案（不区分大小写）

  * 底部：上一题 / 下一题 按钮（最后一题时下一题变 "交卷"）

* 右侧 30%（答题卡，固定不滚动）：


  * 标题 "答题卡"

  * 按题型分组显示题号格子（每个格子 30x30px）


    * 未答：灰色

    * 已答：绿色

    * 当前题：蓝色边框

  * 点击题号跳转到对应题目

  * 底部统计：已答 X 题 / 共 Y 题

### 页面 3：mock\_exam\_result.html（成绩页）



* 顶部：总分（大字体）+ "击败了 X% 的考生"（模拟数据）

* 中部：各部分得分卡片（写作 / 听力 / 阅读 / 翻译，各显示得分率）

* 下部：题目回顾列表


  * 客观题：显示题目、你的答案、正确答案、解析

  * 主观题：显示你的答案 + 参考范文 / 译文

* 底部："重新考试" / "返回选卷" 按钮

### 技术要求



1. 计时器用 setInterval，剩余时间存在 localStorage，刷新页面不丢失

2. 答题进度存在 localStorage，key 格式：`<用户名>_mock_exam_<paper_id>`

3. 交卷后自动计算客观题得分，主观题显示参考答案不自动评分

4. 页面间用 location.href 跳转，传 `?paper=xxx` 参数

5. 原来的攻略内容移到 exam\_guide.html，从选卷页底部链接进入

### 绝对禁止

* ❌ 禁止没有计时器

* ❌ 禁止没有答题卡

## 模块 2：四级阅读理解

**现状问题**：弹窗里 10 道 "技巧题"，没有阅读文章，和 "阅读" 无关。

**改造要求**：做 2 个独立 HTML 页面 + 1 个 JSON。

### 页面 1：reading\_list.html（文章列表页）



* 顶部：标题 "阅读理解" + 难度筛选标签（全部 / 简单 / 中等 / 困难）

* 主体：文章列表，每篇文章一个卡片

  卡片内容：文章标题、主题标签、字数、难度、题数、"开始阅读" 按钮

* 底部：分页或 "加载更多"

### 页面 2：reading\_practice.html（阅读答题页）

顶部固定栏：



* 文章标题 + "第 X 题 / 共 5 题" + "返回列表" 按钮

主体上下布局：



* 上半部分（占 50% 高度，可独立滚动）：阅读文章正文


  * 字体适中，行间距 1.6

  * 段落清晰

* 下半部分（占 50% 高度）：题目区


  * 一道题一道题显示（不是一次性全显示）

  * 选择题：题干 + 4 选项，点击选中

  * 答完一题点 "下一题"

  * 全部答完后显示 "查看结果"

结果展示（答完后在同一页面下方展开）：



* 正确率：X/5

* 每道题：你的答案、正确答案、2 句话解析

* "再做一篇" 按钮

## 模块 4：情景式口语

**现状问题**：和听力训练共用一个页面，只是 "口语跟读" 标签，没有对话。

**改造要求**：做 2 个独立 HTML 页面 + 1 个 JSON，独立于听力训练。

### 页面 1：speaking\_scenarios.html（场景列表页）



* 顶部：标题 "情景口语" + 说明 "角色扮演对话，文字输入练习"

* 主体：场景卡片网格（2 列布局）

  每张卡片：场景名称（如 "咖啡店点单"）、场景图标、难度、轮数、"开始对话" 按钮

### 页面 2：speaking\_dialog.html（对话练习页）

顶部：场景名称 + "第 X 轮 / 共 Y 轮" + "返回场景"

主体（类似聊天界面，占满页面）：



* 对话区（可滚动，占大部分高度）：


  * AI 角色的消息：左侧气泡，带角色头像

  * 用户的消息：右侧气泡

  * 每轮 AI 说完后，底部出现输入框

## 使用方法



1. **先把 "通用前置指令" 发给 AI**，让它记住规则

2. **然后一次只发一个模块的指令**，比如先发 "模块 1：四级模拟模考"

3. AI 输出代码后，测试确认没问题了，再发下一个模块

4. 如果 AI 还是做成弹窗，直接回：

> "我明确说了禁止弹窗，你又做成了弹窗。把弹窗代码删掉，改成独立 HTML 页面，重新输出。"

**核心原则：把页面结构画给 AI 看（顶部放什么、左侧放什么、右侧放什么、底部放什么），它就没有发挥空间，只能按你说的做。**

**多题型原则：模考和练习页面必须支持多种题型混合。如果 AI 只做了单选题，直接回：**

> "我明确说了支持 9 种题型，你只做了单选题。请补充多选题、判断题、完形填空、写作、翻译、听力、填空等题型的渲染组件，写一个统一的 renderQuestion 函数根据 type 字段切换。"

## 多题型支持速查表

所有模考 / 练习页面必须支持以下 9 种题型，根据 JSON 的`type`字段渲染：



| type 值            | 题型   | 渲染方式                   | 判分方式         |
| ----------------- | ---- | ---------------------- | ------------ |
| `single_choice`   | 单选题  | 4 选项卡片，点击即选中           | 自动判分         |
| `multiple_choice` | 多选题  | 4 选项带复选框，有提交按钮         | 自动判分（全对才得分）  |
| `true_false`      | 判断题  | 正确 / 错误两个大按钮           | 自动判分         |
| `reading`         | 阅读理解 | 上方文章滚动区 + 下方小题         | 小题自动判分       |
| `cloze`           | 完形填空 | 文章带编号空 + 每空 4 选项下拉     | 自动判分         |
| `essay`           | 写作题  | 题目 + 大 textarea + 字数统计 | 不自动判分，显示范文   |
| `translation`     | 翻译题  | 中文原文 + 英文 textarea     | 不自动判分，显示译文   |
| `listening`       | 听力题  | 音频播放器 + 题目 + 选项        | 自动判分         |
| `fill_blank`      | 填空题  | 题干带\_\_\_+ 输入框         | 自动判分（不区分大小写） |

**JSON 里每道题必须有**`type`**字段，值必须是上表 9 个之一。渲染函数用**`switch(question.type)`**分发到不同组件。**
