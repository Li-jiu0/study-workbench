## 3. 接口与边界

### 3.1 subpage-router 详细契约（D1 拍板）

> 实现文件：`assets/subpage-router.js`（新增，`?v=20260912a`）。

#### 3.1.1 公共对象

```js
window.SubpageRouter = {
  init(opts)            // 启动入口
  navigate(key, params) // 切换子页面
  back()                // 等同浏览器后退（出栈）
  getCurrent()          // 返回 'list' | 'appearance' | ...
  getParams()           // 返回 { userId: '42' } 等
  onSubpageChange(cb)   // 注册切换回调（业务代码用）
  _stack: []            // 内部栈（不推荐业务直接访问）
};
```

#### 3.1.2 `SubpageRouter.init(opts)` 启动入口

`opts` 必填字段：

| 字段 | 类型 | 说明 | 本批取值 |
|---|---|---|---|
| `rootSelector` | string | 子页面作用域根；只在根内扫描 `[data-subpage]` | `'#page-settings'` / `'#page-profile'` |
| `defaultSubpage` | string | 默认 key（hash 为空时显示） | `'list'` |
| `sectionsSelector` | string | section 选择器 | `'[data-subpage]'` |
| `breadcrumbSelector` | string | 面包屑容器 | `'.subpage-header'` |
| `pageTitle` | string | 第一层显示名（用于面包屑） | `'设置'` / `'个人中心'` |

**行为**：
1. 扫描 `rootSelector` 内所有 `[data-subpage]` 节点，登记为已知 key（非法 hash 时回退到 `defaultSubpage`）。
2. 读 `location.hash`：空/`#` → 显示第一层（隐藏所有 section + 显示分组卡列表 + 面包屑清空）；非空 → 解析出 `key` 与 `params`，显示对应 section + 隐藏其它 + 隐藏分组卡列表 + 渲染面包屑「根 › 分组」。
3. 绑定 `hashchange` + `popstate` 监听。
4. 调一次注册的 `onChange` 回调（init 时也算切换）。

#### 3.1.3 `SubpageRouter.navigate(key, params)` 切换

| 参数 | 类型 | 说明 |
|---|---|---|
| `key` | string | section 的 `data-subpage` 值；`'list'` = 第一层；非法 key → 回退 `defaultSubpage` 并 `console.warn` |
| `params` | object? | 可选；形如 `{ userId: 42 }`；序列化到 `location.hash` 形如 `#moments?userId=42` |

**行为**：
1. 若 `key === 'list'`：`location.hash = ''`（不 push 历史；用 `history.replaceState` 清空）。
2. 否则：`location.hash = '#' + key + (params ? '?' + serializeParams(params) : '')`（**默认 push** 历史，可被浏览器后退）。
3. 内部 push 到 `_stack`（仅 `key` 列表，不含 `list`）。
4. 实际切换由 `hashchange` 监听器驱动（避免重复逻辑）。

**params 序列化**：仅支持 string/number/boolean；其它类型 `JSON.stringify`；读时 `SubpageRouter.getParams()` 反向解析。

#### 3.1.4 `hashchange` / `popstate` 协调（核心陷阱）

- `popstate` 由浏览器前进/后退触发，**浏览器已经更新了 hash**；接着 `hashchange` 也会触发。
- router **必须**只在 `popstate` 触发的 `hashchange` 上**不**重复 push `_stack`（用 `_popping` 标志）。
- `_stack` 在 navigate 时 push；`back()` 时调用 `history.back()` 触发 `popstate` → 设置 `_popping=true` → `hashchange` 触发 → 切换但不 push → `_popping=false`。
- 浏览器后退到 `'list'`：自动回退到默认视图（**不**从 `_stack` 主动 pop，保持简单）。

#### 3.1.5 面包屑渲染规则

| 当前 key | 面包屑 HTML |
|---|---|
| `'list'` | **不渲染**（隐藏 `.subpage-header`）或仅显示「设置」（current 态） |
| `'appearance'` | `设置 › 外观`（根 `href="设置.html"`，点击 = `navigate('list')`；分组 `href="设置.html#appearance"` 仅刷新） |
| 携带 params | 同上；params 不进入面包屑 |

**样式**：`.subpage-header` 见 §5 共享知识。

#### 3.1.6 默认隐藏兜底（CSS-only）

每页 `<style>` 末尾追加：
```css
.subpage-section { display: none; }
```
**目的**：禁用 JS 时所有 section 仍隐藏（不泄漏），CSS-only 兜底；启用 JS 后由 router 切换 `display`。

#### 3.1.7 与 `navigateTo()` 的嵌套关系

- `app.js:819 navigateTo(page)` **不**改签名；subpage-router 是页面**内**的子层路由。
- 业务代码需深链时直接 `location.href = '设置.html#appearance'`；router 自动切换。
- **本批不**扩展 `navigateTo(page, { subpage })` 第二个参数（避免侵入 app.js）。

#### 3.1.8 `onSubpageChange(cb)` 业务回调

`cb(key, params)` 在 hash 切换后调用。本批用法：
- `个人中心.html` 在 `data-subpage="profile"` 激活时调 `api.js:renderProfilePage()` 渲染资料卡。
- `data-subpage="posts"` 激活时调 `api.js:renderProfilePage()` 的发贴统计部分（若 `renderProfilePage` 是单函数渲染整 `#profileBox`，需拆分或重入；具体在 T03 内消化）。
- `data-subpage="moments"` 激活时调 `renderMyMoments()` 渲染 `myMomentsBody`。
- `data-subpage="privacy"` 激活时调 `stLoadPrivacy()`（批次四 T05 落地的 `设置.html` 函数）。
- 切换前若 `profile` 资料卡有未保存改动 → toast「未保存确认」（R-10 缓解）。

### 3.2 subpage-router 与 `app.js` 的关系

| 资源 | 谁提供 | router 消费方式 |
|---|---|---|
| `toggleTheme()` / `showToast()` | `app.js` | router 不直接调用；业务回调（`onSubpageChange`）按需调 |
| `navigateTo(page)` | `app.js:819` | 不调用；router 只管 hash |
| `#countdownModal` / AI 悬浮窗 | 各页 DOM | router 不触碰；这些是页面级共用 |
| `setTimeout/Date` | 浏览器原生 | 解析 hash 形如 `#moments?userId=42` |

**关系定位**：subpage-router 是 `app.js` 之后**独立**加载的子层路由；与 `app.js` 零侵入（不调 `navigateTo`，不调 `toggleTheme`）。

### 3.6 生日格式 normalize 规则（#5 个人资料）

> 新增 `assets/normalize-birthday.js`？**不**，**追加**到 `个人中心.html` 内联脚本或 `assets/api.js`（与 `saveProfileEditor` 同处）；建议**追加到 `个人中心.html` 底部现有内联脚本**（避免动 `api.js`）。函数 `window.normalizeBirthdayText` 与 `window.peBirthdayOnBlur`。

#### 3.6.1 输入格式 → 归一化表

| 输入示例 | 处理 | 输出 |
|---|---|---|
| `19900102`（8 位纯数字） | `/^(\d{4})(\d{2})(\d{2})$/` 拆 | `1990-01-02` |
| `1990-01-02` | `/^(\d{4})[-./\s](\d{1,2})[-./\s](\d{1,2})$/` 拆 + `padStart` | `1990-01-02` |
| `1990.01.02` / `1990/01/02` / `1990 1 2` | 同上 | `1990-01-02` |
| `1990年1月2日` / `1990年01月02日` | `/年|月|日/` 拆 | `1990-01-02` |
| `abc` / `1990-13-40` / 越界 | 校验失败 | **保留 text 原值 + 红字提示 + 不破坏 `peBirthday` 原值** |

#### 3.6.2 校验规则

1. 年：`1950 <= y <= 2015`（与 `个人中心.html:165` min/max 一致；铁律 5 隐私红线要求服务端契约 `YYYY-MM-DD`）
2. 月：`1 <= m <= 12`
3. 日：`1 <= d <= 31` + **闰年 / 大小月真实天数**（用 `Date(y, m-1, d)` 构造后 `getFullYear()/getMonth()/getDate()` 反查防 `02-29` 跨年）
4. 失败条件：任一不满足 → `peBirthdayOnBlur` 保留 `peBirthdayText` 原值 + 在下方显示红字 `<div class="pe-bd-err" style="color:var(--danger);font-size:12px;margin-top:4px">日期格式不对，参考：1990-01-02</div>`

#### 3.6.3 落库契约

- 成功 → **写回** `peBirthday.value = '1990-01-02'`（保持 YYYY-MM-DD）+ 清空 `peBirthdayText.value` + 移除红字提示。
- `api.js:1405 birthday = (bEl && bEl.value) || ''; api.js:1413 body.birthday = birthday` 继续读 `peBirthday.value` —— **不破坏**。
- 失败 → `peBirthday.value` 保持不变（不破坏用户已用 date picker 选好的日期）。

#### 3.6.4 触发时机

- `<input type="text" id="peBirthdayText" onblur="peBirthdayOnBlur()">`
- 不在 `oninput` 触发（避免每个字符都校验 + 红字闪烁）。
- 范围校验：>2015 或 <1950 同样红字提示「日期需在 1950-01-01 到 2015-12-31 之间」。
