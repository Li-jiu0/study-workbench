### 3.3 subpage-router 设计契约（Q1 拍板：B-改良版 hash 路由）

> 本节是 #1 多级面包屑的核心设计契约。架构师实现 `assets/subpage-router.js` 时**必须**满足以下全部要点。

#### 3.3.1 形态与零侵入

- **零新 HTML**：所有分组详情都在原 `设置.html` / `个人中心.html` 内作为 `<section data-subpage="appearance">` 存在；`subpage-router.js` 加载后扫描 `[data-subpage]` 节点、自动维护可见性。
- **嵌套于 `navigateTo()` 之下**：subpage-router **不**改 `assets/app.js:819 navigateTo()`；原页面切换（`navigateTo('settings')`）照旧。subpage 是页面内的**子层路由**。
- **共享 DOM 不动**：因为不新建页面，`#countdownModal` / `.bottom-nav` / `.sidebar` / `.topbar` / `#toast` / AI 悬浮窗全部沿用现成——**避免批次四 R-1（缺 `#countdownModal` 致 `app.js:1213` 抛错）复发**。

#### 3.3.2 API 契约

| 符号 | 类型 | 行为 |
|---|---|---|
| `window.SubpageRouter` | 对象 | 公开命名空间，含 `init/navigate/onpopstate/getCurrent` |
| `SubpageRouter.init(opts)` | 函数 | 启动入口；`opts = { rootSelector: '#page-settings' \| '#page-profile', sectionsSelector: '[data-subpage]', defaultSubpage: 'list', breadcrumbSelector: '.subpage-header' }` |
| `SubpageRouter.navigate(key, params)` | 函数 | 切换到 key 对应 section；`params` 可选（如 `moments` 分组传 `?userId=...`） |
| `SubpageRouter.getCurrent()` | 函数 | 返回当前子页面 key（`'list'` = 第一层分组列表；或 `'appearance'` / `'privacy'` 等 section key） |
| `SubpageRouter.onSubpageChange(cb)` | 函数 | 注册切换回调，供业务代码（如 `renderProfilePage` 在 `profile` 激活时调） |

#### 3.3.3 URL hash 格式

- 第一层（分组列表）：无 hash 或 `location.hash === ''` 或 `'#'`，显示第一层 6/5 张分组卡，所有 `[data-subpage]` 隐藏。
- 第二层：hash 形如 `#appearance` / `#privacy` / `#profile`，显示对应 `<section data-subpage="appearance">`，其它 section 隐藏，**第一层分组卡也隐藏**。
- 携带参数：hash 形如 `#moments?userId=123`；`SubpageRouter.navigate('moments', { userId: 123 })` 自动写入 `location.hash`；读取时用 `SubpageRouter.getParams()` 返回对象。
- 非法 hash（未注册的 key）：回退第一层（不报错、不留空白）。

#### 3.3.4 浏览器前进/后退

- 监听 `window.addEventListener('hashchange', ...)`：hash 变化即切换 section。
- 监听 `window.addEventListener('popstate', ...)`：浏览器前进/后退触发，**优先于 hashchange** 同步状态。
- 内部用栈（`SubpageRouter._stack = []`）记录子页面历史，支持 `SubpageRouter.back()` 调用等同浏览器后退。

#### 3.3.5 面包屑生成规则

- `.subpage-header` 由 router 维护，HTML 结构：
  ```html
  <div class="subpage-header">
    <a href="设置.html">设置</a> <span>›</span>
    <a href="设置.html#appearance">外观</a> <span>›</span>
    <span class="sub">主题</span>   <!-- 仅进入设置项最深一层时显示；本批暂不实现"项"层 -->
  </div>
  ```
- 第一层：面包屑隐藏或仅显示「设置」/「个人中心」（点击无操作，current 态）。
- 第二层：面包屑显示「**根** › **分组**」，根可点击回第一层（实际是 `SubpageRouter.navigate('list')` + 清 hash）。
- **本批不做"项"层**（即"主题"等单项设置的更深一层）—— 单项设置仍直接落在对应 `<section>` 内的原 card。Q1 拍板后该项废弃。

#### 3.3.6 默认隐藏与初始化

- 所有 `<section data-subpage="...">` 在 `<style>` 末尾加 `.subpage-section { display: none; }` 兜底（CSS-only，禁用 JS 也安全）。
- router `init()` 时按 `location.hash` 决定显示：空 = 第一层；非空 = 对应 section。
- 切换到第一层（无 hash）时，**不**调用 `history.replaceState`（避免污染浏览器历史栈）。

#### 3.3.7 与 `navigateTo()` 的嵌套关系

- `navigateTo('settings')` 切到设置页 = `location.href = PAGE_FILES.settings = '设置.html'`，**无 hash** → router 自动显示第一层。
- `navigateTo('settings', { subpage: 'privacy' })`（扩展 `navigateTo` 第二个参数，可选）→ `location.href = '设置.html#privacy'`，router 自动显示隐私分组 section。**本批 `navigateTo()` 不改签名**，仅 router 监听 hash；业务代码需深链时直接 `location.href = '设置.html#privacy'`。

#### 3.3.8 file:// 直开兼容

- hash 路由在 `file://` 下无 CORS 限制，原生支持；router 不依赖任何 fetch。
- 测试用：`file:///D:/下载的文件/学习工作台/设置.html#appearance` 直接打开应进入外观分组。
