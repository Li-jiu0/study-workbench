## 一、产品目标

星途已从「学习工具」长成「学习社区 + 多模块学习站 + 手机构筑（APK）」，但快速迭代留下了三类问题：**看起来坏掉的缺陷**（群聊弹窗定位、头像误触、修改密码不可用、语音不可用）、**结构割裂的体验**（底部「更多/工具」是临时弹层、资料页与设置页信息散乱、全局无搜索、分享缺失）、以及**止步于骨架的新模块**（四级七子模块、学习页千篇一律、英语缺乏沉浸、笔记与 PPT 模板库、文件导入还靠手选）。本轮目标：

1. **修复比新增更重要**：把用户点名的 8 类「坏了/看着不对」的问题彻底修好，让既有功能看起来、用起来都可靠（**批次一，最高优先**）。
2. **把体验从「能用」推到「顺手」**：资料页与设置页重构、设置项全站生效、隐私与安全成体系、全局搜索、性能与分享补齐，让信息架构清晰（**批次二**）。
3. **把骨架模块做实**：四级七子模块各有入口与进度、四个学习页各有独特气质、英语走向沉浸式、笔记与 PPT 模板库可用、文件导入自动识别目标，形成可留存的学习闭环（**批次三**）。

### 4.1 群聊弹窗（A1）—— 正确呈现

- **触发**：私聊页会话列表标题区「👥 群聊」按钮。

## 六、风险与不做清单

### 风险（需架构/开发重点关注）

1. **双轨兼容（最大风险）**：同一套前端要同时在「file:// 直开 + 单机」与「在线（`api.js`）」两种环境运行；历史教训——**APK 内 `api.js` 被剔除**，故所有新功能必须「无后端也能用/明确提示」，且每次改动后**必须抽查包内文件与源码关键符号一致**（"代码修好 ≠ 包里有"）。
2. **Android WebView 能力边界**：QA 实测 **TTS / 朗读 / `voiceplayer.js` 均正常**；受制约的是**语音识别**（仅 Chrome + 授权可用，WebView 内受限）。故 A7 已拆分：①**新增聊天语音消息**（`MediaRecorder`，无权限/非 Chrome 时优雅降级）②语音识别非 Chrome 给**降级提示**。**本轮不做「TTS 修复」。**
3. **隐私红线回归**：B3/B4/B6 新增接口与分享海报务必走 `user_brief` 白名单，**绝不返回 phone/gender/birthday**；建议保留字符串级回归断言。
4. **旧库无损升级**：`users`/`notes` 加列必须走守卫式 ALTER，默认值取最保守值；上线前用旧库副本验证启动无损。
5. **性能优化不得换架构**：性能（B5）只能在「原生 JS + 分页 + 懒加载 + 轮询节流」内做，**不得引入框架或独立进程**。
6. **版本号与打包纪律**：所有被改 HTML 的 `?v=` 统一 bump；新页与 JS 一律带版本号；APK 重打包后校验签名/zipalign/包内符号。
7. **不删原 DOM/原功能**：A8 弹层、C5 旧三页、A3 旧样式均**保留可回退**，避免回归。
8. **QA 清单已收敛，A1/A2 仍待复验**：需求池「现状」列已按 QA 首轮盘点落定；A1/A2 首轮**未复现**，正以真实账号 + 移动端视口做第二轮复验——**若复现按根因修，若确认不复现则改为健壮性加固**（详见批次一 A1/A2 行），最终方案以复验结论为准。

### 不做清单（本轮明确不做）

- ❌ 好友间实时语音/视频通话（WebRTC + 信令 + NAT 穿透，架构成本极高，沿用上轮结论）。
- ❌ 端到端加密、第三方登录（微信/QQ）、iOS 原生 App。
- ❌ 云原生重构（换框架、拆微服务、上消息队列/Redis）。
- ❌ 账号级实时多端同步（本轮仅「本地优先 + 静默同步」；完整多端同步列后续）。
- ❌ 真实支付/会员/虚拟货币体系。
- ❌ AI 自训模型；AI 能力一律走后端中转，密钥不进前端。
- ❌ 修改密码的「邮箱/短信验证码找回」（无短信/邮件通道，保持「联系管理员重置」）。
