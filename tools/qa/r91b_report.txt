三、根因（实测）

  - assets/common.css L1282-1291（⛔ 根锁文件，未改动）：
    .bottom-nav { position:fixed; bottom:0; height:var(--bottom-nav-height)=64px; z-index:200;
                  padding-bottom:env(safe-area-inset-bottom); }
  - 私聊.html（改前）：#imPlusCss 注入
    .im-plus-mask z-index:60（L1037）、.im-plus-menu z-index:61（L1039）、
    .im-loc-sheet z-index:80（L1057）—— 三者全部 < 200。
  - 菜单 bottom:0 贴屏幕底缘，第 4 项（定位）落在 Tab 栏(64px)覆盖区内，
    且 z-index 61 < 200 → Tab 栏压在菜单上，第 4 项只露顶部一条边。与截图现象完全一致。

四、改动点（最小改动，仅 私聊.html #imPlusCss 注入串 3 处 z-index）

  工具：tools/qa/_r91b_patch.py（字节级替换，open(p,'rb')→replace→'wb'，不触行尾）
  1. L1037  .im-plus-mask  z-index:60  →  z-index:210   （遮罩盖住全屏含 Tab 栏）
  2. L1039  .im-plus-menu  z-index:61  →  z-index:211   （菜单浮于 Tab 栏之上，微信弹层范式）
  3. L1057  .im-loc-sheet  z-index:80  →  z-index:215   （同源问题一并修：定位半屏层也低于 200）
  层级序：Tab 栏 200 < 遮罩 210 < 菜单 211 < loc-sheet 215 < toast 2000 < 消息菜单 10000+。
  方案取舍：Tab 栏为 fixed bottom:0 / 64px+safe-area / z-index:200（common.css 根锁）。
  采用「遮罩+菜单整体抬到 200 以上」而非「菜单 bottom 预留 64px」：后者在桌面宽屏
  （.bottom-nav display:none，媒体查询 ≤768px 才显示）会造成菜单悬空 64px，需再补媒体查询，
  改动面更大；抬 z-index 一处改动即同时覆盖移动/桌面，且与 R89-A 的全屏遮罩 bottom-sheet
  范式一致（遮罩把 Tab 栏一并罩住变暗不可点，即微信行为）。
  R89-A 已有项（max-height:82vh + overflow-y 内滚 + @media max-height:520px 矮屏查询）
  经核实已在位，未重复添加。
