二、卡死时调用栈（关键证据，Debugger.paused 捕获）

三、根因
--------------------------------------------------------------------------------
个人中心.html 内联脚本（xtWatchAccount，原 L1481-1487）用 MutationObserver 监听
#profileBox {childList+subtree}，回调执行 xtRenderAccount()：
  xtRenderAccount → el.textContent = ...（原 L1289）
  xtInjectAccountRow → row.textContent = '账号：'+...（原 L1281）
textContent setter 即使写入相同值也会**重建文本节点** → 每次回调都产生新的
childList 突变 → observer 再次入队回调 → 「观察→渲染→再观察」无限微任务循环，
渲染与输入事件完全饿死 → 页面永久卡死。
触发条件：页面驻留（带登录 token，不会被登出重定向）即触发，与 file:// 无关，
file:// 双击打开是用户的主路径所以暴露。该 Bug 与 R91-A 改动无关
（个人中心.html 不加载 xt-profile.js）。

四、修复（最小改动，个人中心.html，二进制编辑+行尾回读）
--------------------------------------------------------------------------------
FIX1  原 L1281（现 L1281-1285）：xtInjectAccountRow 行文本写入加守卫
      var acctText = '账号：' + (a || ACC_EMPTY);
      if (row.textContent !== acctText) { row.textContent = acctText; }
      + R91-C 注释说明根因。
FIX2  原 L1288-1291（现 L1292-1297）：xtRenderAccount 的 peAccount 写入加守卫
      var accVal = a || ACC_EMPTY;
      if (el.textContent !== accVal) { el.textContent = accVal; }
      className 赋值保留（attribute 突变不在监听范围内，不会自触发）。
策略：幂等守卫让突变序列「 settles」——首轮回调后再无新突变，循环自然终止；
不改动 observer 结构与任何既有行为。
（同文件 L1004 另一个 observer 回调带 parentNode/host 幂等早退，会收敛，未动。）
